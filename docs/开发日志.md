## 2026-11-19 代码与链接冷色

**总结：正文的块、线、装饰都是暖色系，行内代码和链接认不出来；代码换蓝灰、链接换蓝，橘色只留给装饰。**

固件：不适用，主题仓库无固件，提交 1dbedf7。同批改动：无。

### 背景/现象

- 用户反馈页面都是一个色系，不太方便阅读。

### 原因分析

依据等级：实测，WCAG 对比度计算加截图。

- 行内代码是灰字 #808080 在米色底 #f6f1e7 上，对比度 3.51:1，低于 AA 的 4.5:1，代码和米色块糊在一起。
- 链接是 #666 灰字加灰下划线，看起来像浅一点的正文。
- 代码底、表格线、引用、分隔线都是米色或橘色，元素之间没有区分。
- 行内代码颜色实际由 main.styl 的 `code { color: $theme-color }` 决定，`themeColor` 默认 #808080；配色里的 `--color-text-md-code: #e96900` 在行内代码上被它盖住，只有搜索关键字用到。

### 改动

- color-scheme.css 浅色：行内代码字 #3d5a80、底 #eef1f5，对比度 6.24:1；新增 `--color-md-link` #2f6fb0，5.22:1，`--color-md-link-line` 35% 透明的同色下划线。
- 深色：行内代码字 #a3bfdc，5.29:1，底不变；链接 #88b0dc，5.53:1，下划线 40%。
- github-markdown.css：`.markdown-body a` 和悬浮态改用链接变量，悬浮时下划线变实。
- main.styl：删掉 `.markdown-body` 下代码颜色和链接悬浮下划线跟随 `$theme-color` 的规则。`themeColor` 仍用于目录悬浮等其他地方。
- 搜索结果关键字 `.search-keyword` 也用 `--color-text-md-code`，跟着从橘色变成蓝灰。

### 方案演进

- 截了三版：现状；蓝灰代码加蓝链接；玫红代码 #c7254e 加蓝链接。玫红区分度最高但更热闹，用户选了蓝灰。
- 表格线和代码块底色是否也去掉米色，先不动，看这轮效果再说。

### 审查结论

- 冲突：`.markdown-body pre code` 权重高于 `.markdown-body code`，代码块文字仍用 `--color-text-md-pre`，只有行内代码变色。`.markdown-body` 只包文章、关于、友链页的正文内容，友链卡片不在里面，不受影响。
- 错误置位：原 `--color-text-md-code` 的橘色在行内代码上从未生效，只有搜索关键字在用；改值后搜索关键字从橘色变成蓝灰，已写入 CHANGELOG。
- 自检：verify-preview 65/65；浅色、深色截图 r-final-light.png、r-final-dark.png 符合选定方案。

**总结：沿着像素、橘猫的视觉语言加几处可爱的点缀：文末睡觉的狸花猫、淡橘选中色、头像悬浮跳、回到顶部箭头发射。**

## 2026-11-19 正文块与背景色

**总结：浅色背景从纸色改成纯白；正文里的块原来用 GitHub 冷灰，和底色不搭，改成淡暖色，引用块换成淡橘底加浅橘左线，表格改成只有横线的书籍式，分隔线跟随配色。**

固件：不适用，主题仓库无固件，提交 01f549a。同批改动：2026-11-19 像素睡猫与小动画。

### 背景/现象

- 浅色底是暖纸色 #fefcf8，但引用块 #EEEEEE、表格纯白、斑马纹和边框偏蓝，块像贴上去的。
- 第一轮把各块统一调成米色后，用户反馈融洽了但引用块不好看，表格一般。
- 引用块改成淡橘后，用户觉得颜色仍偏深；表格仍不好看，怀疑与页面背景色有关。
- 表格改完后，用户希望背景再淡一些、更清新。

### 原因分析

依据等级：实测，预览站截图对比。

- 块颜色沿用 GitHub Markdown 的中性冷灰，没有跟着纸色底调整。
- 米色引用块饱和度比底色高，看上去发黄发旧。中性色只能做到不难看，引用块需要主题自己的强调色。
- 引用块左线实际由 main.styl 的 `blockquote { border-color: $theme-color }` 决定，`themeColor` 默认 #808080，配色变量管不到。
- 表格不好看主要是样式：每个单元格四边 2px 边框加斑马纹，五行三列就是一张密网格。背景换成 #faf7f1、#f5f0e6 截图对比，表格观感基本不变。
- 分隔线是 github-markdown.css 写死的 #e1e4e8 和 #eee，深浅两种模式共用，深色下是一条刺眼的浅灰条。

### 改动

- color-scheme.css 浅色：背景 #fefcf8 改为 #ffffff；行内代码 #f6f1e7，pre #ece6da，表格线 #e6dfd2，引用底 rgb(240 138 44 / 3%)。删掉不再使用的 `--bg-block-md-table`、`--bg-block-md-table-2`。
- 新增变量 `--color-border-md-quote`，浅色 #f5b072，深色 #f08a2c；`--color-md-hr`，浅色 #e6dfd2，深色 #4c566a。深色引用底不变。
- github-markdown.css：表格去掉竖线、斑马纹和行底色，单元格只留 1px 底线，表头底线 2px。引用左线改用 `--color-border-md-quote`，分隔线两处写死颜色改用 `--color-md-hr`。
- main.styl：删掉引用块跟随 `$theme-color` 的三行。
- CHANGELOG 同步。预览站 capture-page.js 加 `--dark` 开关，该目录不入库。

### 方案演进

- 第一轮米色引用块，用户觉得不好看。
- 引用块截了五版对比：原灰、米色、半透明黑底、只留橘线、淡橘底加橘线，用户选了最后一版。之后用户觉得偏深，底色从 6% 降到 3%，左线换浅橘 #f5b072。
- 让引用左线变橘有两种做法：把默认 `themeColor` 改成橘色，或者让左线不再跟随它。前者会让行内代码文字、链接悬浮线等一起变橘，等于换全站强调色，没有采用。代价是用户改 `themeColor` 时，引用左线不再跟着变。
- 页面背景试过 #faf7f1、#f5f0e6、#fafafa：加深后表格白底更像贴上去的卡片，没有改善，当时背景保持 #fefcf8。
- 之后用户要背景更淡更清新。#fefcf8 本来就接近白，再淡只能去掉那点黄；对比 #fffefb 和 #ffffff 后用纯白，暖色只留在块上做点缀。
- 表格第一轮只改成暖色，仍是粗网格，用户觉得一般；改成书籍式横线表格。
- 深色模式改成暖深底的方案没有做：代码块 One Dark #282c34 偏蓝，放在暖底上会很突兀，需要连代码配色一起调。

### 审查结论

- 表格：`.markdown-body table th` 原有的 font-weight 规则保留，新规则只加底线粗细，单元格边框规则在前，权重相同、后者覆盖底线宽度。
- 冲突：`--color-block-md-quote` 仍用于引用文字色，左线改用新变量，两者互不覆盖；`themeColor` 其余用途不变。
- 冗余：两个新变量各被引用一到两次；表格两个底色变量已删，全仓库无残留引用。
- 自检：verify-preview.js 65/65 通过；浅色、深色引用块截图与选定方案一致。
- 未覆盖：没有逐页检查评论区、关于页里是否还有引用块或分隔线，按选择器只影响 `.markdown-body` 内部。

## 2026-11-17 座右铭猫尾巴与代码配色

**总结：关于页标题只留名字，座右铭挪到页头全站显示、首页逐字打出；代码配色对齐 One Dark Pro，修掉 Highlight.js 隔行空一行；文章页灯绳换成橘猫尾巴。**

固件：不适用，主题仓库无固件，提交 3ef51ae。同批改动：首页回退与加载优化、关于页与像素点缀、工具条像素图标。

### 背景/现象

- 关于页标题「吃了没？我是南北的猫」读起来别扭。
- 首页只有头像、昵称、导航和列表，显得空。
- 用户 VSCode 用 One Dark，希望代码块配色一致。
- 灯绳是灰线吊一个空心圆，和像素风不搭，用户希望换成小猫尾巴。

### 原因分析

依据等级：实测，截图、计算样式与线上页面 HTML。

- 主题 mac-black 原本就是 Atom One Dark 系，但缺运算符、类名、基础类型等分组；注释 #5c6370 在 #282c34 上对比度约 2.5:1。
- 线上 https://haxiox.github.io/ 用 Highlight.js：每行输出 `<span class="line">…</span><br>`，主题又把 `.line` 设成块级，一行换两次，线上截图里所有代码块都隔行空一行。这是老问题，与本次配色无关。
- 线上 ESP32 那篇 15 个代码块里 14 个没写语言，输出为 plaintext，不生成任何 token，配色再改也是灰的，要在博客侧处理。

### 改动

- 关于页：删掉本批次刚加的 `about.profile.greeting`、`about.profile.motto`，标题只输出名字。
- 页头座右铭 `avatar.motto`：navigation.ejs 把每个字拆成两层 span，外层管出现动画，内层管悬浮波浪，两个动画分层，悬浮结束不会把出现动画重播一遍。所有页面都显示，页头高度一致；只有首页第 1 页带 `motto--typing`，每字间隔 120ms 弹出。配了座右铭时橘色光标从昵称挪到座右铭末尾。
- mac-block.css：按 One Dark Pro 重写 token 分组，同时覆盖 hljs 无前缀类名和 Prism 的 token 类名。隐藏 `.line + br`，空行用一个空格撑起行高。
- pixel.css：灯绳变成 4px 宽、带深色条纹的尾巴，灯泡换成 8×8 卷起的尾巴尖。收起时每 4 秒甩一下，展开时来回摇；位置、命中区、展开高度沿用 catalog-left.css。
- _config.yml、README、README-zh、CHANGELOG 同步；预览站 verify-preview.js 共 65 项。

### 方案演进

- 座右铭第一版设想只在首页显示。那样首页页头多一行，切到其他页导航会上下跳，和之前关于页「怪怪的」是同一个问题，改为全站显示、只在首页打字。
- 打字效果没有用宽度从 0 拉开的写法：中文在等宽字体里的宽度不一定是 2ch，居中文字每出一个字还会整体左移。改为逐字从隐藏到出现，字的位置从头到尾不动；代价是光标一开始就在行尾，不跟着字走。
- 第一版光标隐藏规则 `.avatar--motto .nickname a::after` 和原规则权重相同、排在前面，被覆盖，实测昵称后仍有光标，改成 `.avatar.avatar--motto`。
- `console` 在 hljs 里是 `variable language_`，第一版给了斜体，VSCode 里不是斜体，去掉。`int`、`char` 在 hljs 里是 `type`，第一版归到黄色，VSCode 里是紫色，挪到关键字组。
- 函数参数 `params` 没有标红：hljs 的 params 连括号一起包住，标红会把括号也染红。
- `#define BUF_SIZE 128` 在 hljs 里整行都是 meta，没有更细的 token，整行显示为紫色；Prism 能分出宏名和数字。

## 2026-11-17 工具条像素图标

**总结：工具条的回到顶部、搜索、配色切换、分享四个按钮换成 8×8 像素图标，纯 CSS 遮罩实现，跟随文字色；顺带修复首次访问浅色页面显示太阳的问题。**

### 背景/现象

像素点缀第 ④ 步。工具条四个图标还是阿里 iconfont 的线条字形，和卡片切角、小橘子不是一个风格。

### 原因分析

## 2026-11-17 首页回退与加载优化

**总结：撤回导航左对齐、恢复线上首页格式；去掉无用的 Raleway 字体请求，MathJax 支持按文章加载并修正配置时序，主题路径统一走 url_for 以支持子路径部署。**

固件：不适用，主题仓库无固件，提交 3ef51ae。同批改动：关于页与像素点缀、工具条像素图标、座右铭猫尾巴与代码配色。

### 背景/现象

- 本地预览首页的导航行贴左，和线上 https://haxiox.github.io/ 的居中导航不一致；首页列表也被改成标题在前、日期在后。
- 每个页面在 head 里同步请求 Google Fonts，国内常卡住首屏。
- 每篇文章都下载约 1.1MB 的 tex-chtml.js，示例 9 篇里只有 1 篇用到公式。
- 部署到子路径时，主题手写的根路径资源会 404。

### 原因分析

依据等级：实测，截图和 curl/grep 结果；时序竞争一项为文档推算，未复现。

- 首页差异来自工作区里一处未提交的 base.css 改动，不是预览出错。截图对比：HEAD d6f9415 与线上一致。
- Raleway 在 base.css 里的两处引用都已注释，字体请求纯属浪费。
- mathjax.ejs 把 async 的 MathJax 脚本写在 `MathJax = {...}` 配置之前，脚本命中缓存时可能先于配置执行，行内 `$...$` 失效。
- header、clipboard、comments、mathjax、search、navigation、footer、post 里共有十多处手写 `/css`、`/plugins`、`/search.xml` 或直接输出配置里的路径，未经过 url_for。hexo 的 css()、js() 助手本身已带 url_for，不受影响。

- header.ejs：删除 Raleway 的 link。
